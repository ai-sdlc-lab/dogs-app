# SPEC-0004: Invalid input returns 422 with the standard error body and is logged as `input.rejected`

<!-- Stage 2, derived from INT-0004.md. Behaviour and numbers, not implementation. -->

## 1. Behaviour

Scope: the only external input of the API is the `breed` path value of `GET /api/dogs/{breed}`. `GET /api/dogs` and `GET /api/health` take no input (query strings and headers are ignored, as today).

1.1 **Allowed breed.** A breed is valid only if the whole value is 1 to 40 characters, each one of `a-z`, `0-9`, `-` (ASCII only). The rule is unchanged, with one clarification: the whole value must match, so a value with a trailing newline (`pug%0A`) is invalid. Today such a value passes the check; this change closes that hole. The value is the percent-decoded path segment; bytes that are not valid UTF-8 decode to a replacement character and are therefore invalid.

1.2 **Rejection.** An invalid breed gets status `422` and the body `{"error": "invalid_input", "request_id": "<id>"}`, `Content-Type: application/json; charset=utf-8`. Nothing is read from S3 for a rejected breed.

1.2a **Whole-value match everywhere.** The same whole-value rule (1.1) applies to the breed segment of every object key returned by the S3 listing: a key whose breed segment ends in a newline (or otherwise fails the rule) is skipped, never turned into a presigned URL.

1.3 **Body content.** The body has exactly the two keys above. It never contains the submitted value, a field name, the word `detail`, a path, exception text or library text. Nothing from the request is copied into any response header.

1.4 **Request ID.** `request_id` is the Lambda request ID from the platform context, or, if the context has none, a freshly generated ID of 32 lowercase hex characters (128 random bits from a CSPRNG). Never a request header or query value. The `503` of change 0003 uses the same rule, so its generated-ID format changes with this change: the existing `test_503_request_id_generated_when_missing` is updated from UUID v4 to the 32-hex format.

1.5 **Framework validation.** Any other failure of the framework's own request validation (present or future parameters) gets the same `422`, body and log event. The framework's default `422` body is never sent.

1.6 **Unchanged.**
- A valid breed with no images (for example `husky`) returns `404` with today's body. A missing resource is not invalid input.
- A found breed returns `200` with today's list; `/api/dogs` and `/api/health` are unchanged; `503` for S3 failure is unchanged.
- A path with an encoded slash (`/api/dogs/a%2Fb`) or an empty breed (`/api/dogs/`) does not match the breed route and keeps today's `404`. No breed value reaches validation, so no `input.rejected` event is written for them.
- Unknown routes, `405`, and the `404` bodies are unchanged (SR-005 for them is #30).

## 2. Interfaces

| Endpoint | Caller | Input | Limit / allowed values | On violation |
|---|---|---|---|---|
| `GET /api/dogs/{breed}` | anyone (public, no login) | `breed`, path segment, string | 1 to 40 characters; `a-z`, `0-9`, `-` only; whole value; valid UTF-8; no control characters (they are outside the character set) | `422`, body per 1.2, event per 6.2 |
| `GET /api/dogs` | anyone | none | n/a | n/a |
| `GET /api/health` | anyone | none | n/a | n/a |

No endpoint accepts a request body, so there is no JSON body, unknown-field or 64 KiB rule to apply (SR-001). Query strings are ignored and never validated, used or logged. Numbers and enumerated values: none are accepted.

## 3. Limits

- Breed: 1 to 40 characters.
- Logged `http.path`: at most 200 characters (truncated beyond that), so a log event has bounded size.
- No new timeouts, rates, quotas or sizes. Current values in `infra/main.tf`, unchanged by this change: Lambda timeout 10 seconds (SR-007 maximum), memory 128 MB, fixed in infrastructure code. S3 limits are unchanged.
- Reserved concurrency: none is set. This is the SR-007 lab exception (the account Lambda concurrency limit is 10, shared, so reserving is not possible; recorded in the lab BASELINE). Rate limiting is not added: the endpoint is read-only and does no write or heavy work.
- Flood volume of invalid requests is bounded by the 200-character path cap per log line and by the account Lambda concurrency limit of 10 (shared).
- Each rejected request now adds one log event (CloudWatch ingestion cost). Worst-case line size is about 1.5 KB (path of 200 characters, each escaped to up to 6 bytes, plus the fixed fields); a typical line is under 0.5 KB. Upper bound of a sustained flood: 10 concurrent invocations at about 10 ms per rejected request is about 1,000 events per second, which is about 1.5 MB per second, about 5.4 GB per hour of ingestion (rough figure; real rates are lower because of function start and network time). This new cost is accepted residual risk. A log-volume alarm or budget alert is not part of this change; issue #38 adds it.

## 4. Authentication and identities

None. The API is public and read-only; no login exists. The log field `actor` is therefore always `anonymous`.

| Action | Anonymous caller |

## 6. Data inventory

| Data | Purpose | Storage | Retention | Personal? |
|---|---|---|---|---|
| Submitted breed, only as part of the request path (no query string, at most 200 characters) | Tell invalid input from a missing breed | `input.rejected` log event only; never in a response | 7 days | No (untrusted, caller-controlled) |
| Request ID, method, status 422, reason `invalid_breed` | Trace a rejected request | log event | 7 days | No |
| Source IP | Security monitoring: spotting and tracing repeated hostile input; used for nothing else | log event | 7 days (SR-024 lab exception) | Yes, under many privacy regimes |
| Error response (`error`, `request_id`) | Tell the caller the input was invalid | not stored | none | No |

Storage: the Lambda log group `/aws/lambda/<function name>` (`infra/main.tf`). It has a retention of 7 days and no customer-managed key set, so its data is encrypted at rest by CloudWatch Logs with the AWS-managed service default (SR-023 lab exception: AWS-managed keys, no customer key revocation). This change makes no infrastructure change. The application role can create log streams and put log events, not read or delete them (unchanged).

## 7. Errors and logging

7.1 **What the caller sees.** `422` as in 1.2 to 1.4. Same SR-004 headers as every other response (see 9, SR-004).

7.2 **Event `input.rejected`.** For each rejected request exactly one JSON object on one line on stdout (JSON Lines, collected by CloudWatch), written by the JSON encoder so newline, control and quote characters in values cannot forge or break entries (SR-024):

| Field | Value |
|---|---|
| `ts` | RFC 3339 UTC with milliseconds, e.g. `2026-11-03T10:15:30.123Z` |
| `level` | `WARN` |
| `event` | `input.rejected` |
| `outcome` | `failure` |
| `request_id` | the value in the response body |
| `actor` | `anonymous` |
| `source_ip` | from the platform request context; never from `X-Forwarded-For` or any other header; `unknown` if the context has none |
| `http` | `{"method": "<actual request method>", "path": "<path>", "status": 422}` (the method is the real one of the request, not a constant) |
| `reason` | `invalid_breed` for the breed rule; `invalid_request` for any other framework validation failure (1.5) |
| `service` | `dogs-app` (decided) |
| `version` | the git commit SHA of the build, embedded in the Lambda package at build time; `unknown` only when the package carries no build info (for example local test runs) |

`resource` is omitted: the submitted value is not a resource that exists and appears only in `http.path`.

`http.path` is the actual request path (percent-decoded as the application sees it), without the query string, truncated to 200 characters. The query string appears nowhere in the line. The submitted value appears in the log only in this field and never in the response.

7.3 **Never logged:** headers (including `Authorization`, `Cookie`, `X-Forwarded-For`), request bodies, the query string, exception text, presigned URLs.

7.3a **Logging failure.** If writing the event fails for any reason, the caller still gets the same `422`, body and headers (1.2 to 1.4); no trace, exception text or `500` reaches the response.

7.3b **Log content is untrusted data.** The path in an event is attacker-written text, JSON-escaped. Readers, log viewers and agents treat it as data, never as instructions (SR-031). Volume per request is bounded by the 200-character path cap, and overall by the account Lambda concurrency limit of 10 (3).

7.4 **Other outcomes write no `input.rejected`:** `200`, `404` (valid breed without images, unknown route) and `503` responses. This change adds no other log events (the rest is #38); the `503` path still writes no application log record.

## 9. Security requirements

| SR | How satisfied (section) |
|---|---|
| SR-001 | Explicit rule for the only input (1.1, 2); character set, length 1 to 40, UTF-8, control characters rejected; no body, number or enum inputs (2); `422` with the SR-005 body (1.2) and `input.rejected` (7.2). Tests `test_*_rejects_*` per rejected class (10). |
| SR-002 | The breed reaches S3 only after validation passed: the S3 prefix is the fixed `dogs/` plus the validated breed plus `/`, and for a rejected breed no S3 call is made at all (1.2). The returned object keys are re-checked with the same whole-value rule before use (1.2a; test `test_listing_skips_key_with_trailing_newline`). No shell, `eval`, `exec`, `pickle`, `yaml.load` or similar is applied to request data; no query language is built from the request. |
| SR-003 | Responses are produced by the JSON serialiser; the `422` body is two fixed keys with no request data (1.3). No frontend change. |
| SR-004 | The `422` has `Content-Type: application/json; charset=utf-8`, `X-Content-Type-Options: nosniff`, `Strict-Transport-Security: max-age=31536000; includeSubDomains`, `Referrer-Policy: no-referrer`, as every response; no CORS headers. Test `test_security_headers` includes the `422` case. |
| SR-005 | Fixed body `{"error": "invalid_input", "request_id": "<id>"}` for validation failures, no internal detail (1.2 to 1.5). The general 4xx/404/500 body and `error.unhandled` stay with #30 (INT-0004 out of scope); this is a deviation for those only, not for the 422. |
| SR-006 | Applicable, unchanged: no outbound call is added. | SR-007 | Applicable, unchanged: timeout 10 s, memory 128 MB, reserved-concurrency lab exception, no write or heavy work added (3). |
| SR-021 | Applicable (random identifier). The fallback request ID has 128 random bits from a CSPRNG (32 hex characters), as the rule requires; test `test_generated_request_id_is_128_bit_hex`. | SR-023 | Log events go to the existing CloudWatch log group, encrypted at rest with the AWS-managed service default; retention 7 days (6). No other store is added. No customer-managed key (lab exception). |
| SR-024 | Format, mandatory fields, JSON encoding, path rule, never-logged list (7). `input.rejected` is one of the mandatory events; the 7-day retention is the lab exception. `service` and `version` as in 7.2 (`version` test `test_rejected_log_version_from_build_info`). Schema test `test_rejected_logs_input_rejected_event`. |
| SR-022 | Applicable, unaffected: no new listener or connection; HTTPS-only is kept by the HSTS header (SR-004 row). |

| SR-026 | No secret is used or logged. |
| SR-027 | No dependency added or changed. |
