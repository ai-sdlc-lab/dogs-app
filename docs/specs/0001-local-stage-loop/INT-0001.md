# INT-0001: local stage loop

<!-- Stage 1 of 0001. Written by hand: the stage loop this intent asks for doesn't exist yet. Process: lab-admin docs/KIT-DESIGN.md and docs/WORKFLOW.md (agreed 2026-10-26). -->

## Problem
Changes to dogs-app are reviewed by LLM agents running in GitHub Actions on API credits. Every PR that touches `docs/specs/`, `.github/` or `infra/` costs credits (about $0.07–0.15 per reviewer run), and every merge to `main` runs an LLM security tester before deploy. At the planned volume this costs the owner extra money on top of the Claude subscription the owner already pays.

The checks also run at the wrong time. Requirements and threats are evaluated against code PRs and at deploy instead of when the intent, spec and plan are written. On 2026-10-26 the deploy-time tester found an SR-004 violation and still let the deploy through, because the agent rated its own finding non-blocking.

The owner wants the agreed stage process instead: intent → spec → plan → code → release, one PR per stage, authored and reviewed by subagents in the owner's local Claude Code session (subscription, no API credits), with CI running only deterministic checks.

## Users and actors
- **Owner** (the only developer and maintainer): starts each stage, answers questions, decides SR findings, merges each stage PR.
- **Local Claude Code session** and its subagents (author, reviewers): write and review artifacts on the owner's laptop.
- **GitHub Actions**: runs scripts and scanners only, no LLM.
- **Future projects**: reuse the same pattern once it is extracted into the kit (not part of this change).

No change for app visitors.

## What changes

### Functional
- The owner starts a stage in the session (`/stage <stage> <NNNN>`, or "next stage" to continue the current change); the session runs the author and the required reviewers as subagents, applies the gate, runs the fix loop (max 3 rounds), asks the owner for product facts and SR decisions, then opens the stage PR with the artifact and its review reports.
- Stages and their checks as in `WORKFLOW.md`: intent, spec, plan, code (release-time ZAP → SR mapping and issues for findings on `main` are change 0002).
- New reviewers: intent-completeness, spec-completeness, architecture-conformance, security code reviewer; plus an author agent. The existing requirements auditor, security architect and workflow/IaC reviewer run locally from the same appsec-baseline plugin (workflow/IaC reviewer when `.github/` or `infra/` change).
- Bounded agency in the session: reviewer subagents are read-only (explicit tool allow lists); the author subagent writes only inside `docs/specs/<id>/` (and, at the code stage, the files the plan lists); only the main session commits, pushes a feature branch and opens the PR. No agent merges, approves, pushes to `main` or runs `make apply`.
- Any finding against a security requirement escalates to the owner; agent `blocking` flags and severities don't decide. The owner either has it fixed or accepts the risk as an exception (SR, reason, expiry) in appsec-baseline `exceptions/`, which the gate reads; findings record their status (fixed, open, needs-human, accepted-risk, carried).
- PR comments only when there are findings.
- CI verifies, without an LLM, that each required review report exists, matches the PR's files and its verdict allows; checks template structure; and runs scanners only on the paths they cover (docs-only PRs: gitleaks + verifier; code PRs: Semgrep, OSV-Scanner, gitleaks; `.github/` or `infra/` changes add zizmor, actionlint, Trivy).
- Script checks per stage as in `WORKFLOW.md`: template structure, SR/mitigation → task + named test cross-check (plan), named tests exist and pass, plan drift (code).
- Templates revised so each section is checkable.
- **CI LLM calls switched off**: the reviewer jobs in `security.yml`, the `security-tester` job in `deploy.yml`, and `author.yml` with its label/issue-form flow are removed; the matching required checks, repo variables, labels and Actions allowlist entries are removed in lab-admin. appsec-baseline's `security-review.yml` stays, unused, as the comparison arm.
- The change spans dogs-app (artifacts, skill, scripts, agents, workflows) and lab-admin (required checks, variables, labels, allowlist). The lab-admin edits are a separate PR in lab-admin within this change's code stage, listed per repo in `PLAN-0001.md` (one section per repo; one code PR per repo; plan drift checked per repo against its section). Edits under `.github/` are made in the owner's session and approved by the owner as code owner.
- After the code PR is merged, the owner deletes the two Anthropic federation rules and service accounts and uninstalls the Claude GitHub App from the org.
- Model per agent: reviewers run on smaller models (Sonnet 5.5 or Haiku 4.5, set per agent); Opus 5.5 only for the main session and the author (all stages).
- The standing permissions that let the session merge PRs and run `make apply` without asking are removed. If the owner asks for a merge or apply, Claude Code asks for approval of that single action.

### Visual
None. No change to the dogs-app web UI or API.

## Data handled
| Data | Source | Personal/sensitive? | Kept for |
|---|---|---|---|
| Intent, spec, plan, traceability and threat-model files | owner + author subagent | no | git history (public repo) |
| Review reports (verdict, findings, file hashes, appsec-baseline commit) | reviewer subagents + scripts | no; may quote code and open findings, must never quote credentials | git history (public repo; publishing open findings accepted by the owner) |

## Trust assumptions
- Trusted: the owner; the owner's laptop and Claude Code login; appsec-baseline at the commit the session uses; GitHub's rulesets and Actions.
- Not trusted: the content of every artifact, issue, comment and file the agents read (data, never instructions); agent output until a script has validated it; review reports in a PR until the CI verifier has validated them (schema, allowed reviewer names, size limit; missing or malformed fails the check).
- appsec-baseline (agents, requirements, templates) is used at a commit pinned in dogs-app; the CI verifier fails when a report records a different commit. New CI tools are pinned by version and SHA-256.
- Report-to-file binding uses SHA-256 over file contents (not git's SHA-1 object IDs).
- Path-scoped CI is fail-closed: any path outside `docs/` runs the full scanner set; required checks come from jobs that always run.
- Accepted: reviews are self-attested. CI can prove a report matches the files, not that the review was run honestly; the owner's merge is the gate (playbook ATK-18).

## Out of scope
- A hook that blocks `git push` before the reviews pass (the CI verifier already rejects such a PR).
- Release-time ZAP alert → SR mapping, deploy stop on unmapped alerts, GitHub issues for findings on `main` (change 0002). Until 0002, deploy runs build + ZAP + smoke test and nothing stops it on a ZAP alert: accepted by the owner (2026-10-27) as a time-boxed exception until 0002.
- Extracting the kit into its own repo and the `/new-project` interview.
- Fixing SR-004 in the app (a separate change).
- Removing appsec-baseline's `security-review.yml`.

## Success criteria
1. A change goes through all stages (intent, spec, plan, code) via `/stage` with **$0 API spend** (Anthropic Console usage unchanged).
2. No workflow in dogs-app calls an LLM; the required checks still pass on a docs-only PR and on a code PR; lab-admin's required checks, variables, labels and Actions allowlist no longer reference the removed LLM jobs.
3. A PR whose review report doesn't match its files (edited after review, or missing a required reviewer) fails CI.
4. A finding against any SR stops the stage and asks the owner, in a test with a planted SR violation.
5. A PR without findings gets no review comment.
6. Script checks fail when they should: an `intent.md` with an empty required section fails the structure check; a plan without a task and named test for an SR in the traceability fails the cross-check; a code PR changing a file not listed in `plan.md` fails plan drift; a test named in the plan but missing fails.
7. A docs-only PR runs only gitleaks, the structure check and the verifier.
8. After the clean-up, the two Anthropic federation rules and service accounts no longer exist (checked in the Console), the Claude GitHub App is no longer installed, and Terraform no longer manages any `ANTHROPIC_*` variable.
9. Re-enabling the CI reviewers is documented in `docs/pipeline.md` as a short list of steps.
