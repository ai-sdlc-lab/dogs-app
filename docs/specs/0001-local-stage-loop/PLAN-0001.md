## Lock changes during this change
If appsec-baseline changes after the lock is taken (e.g. a fix found in the dogs-app code stage): a new appsec-baseline PR to `main` (owner approves), new lock SHA in `appsec-baseline.lock` and the `verify.yml@` pin, and every review report whose `appsec_sha` differs is regenerated by re-running that review. The verifier rejects stale `appsec_sha` values, so nothing can be missed.

The appsec-baseline PR that introduces its `scanners` job is not yet gated by it as a required check (L-01 adds it later). The scanners still run on that PR; the owner's approval of the merge to its `main` is the gate. Decided default (plan stage), no interim ruleset change.
