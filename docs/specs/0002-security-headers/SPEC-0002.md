# SPEC-0002: Security response headers on every response (SR-004)

<!-- Stage 2, derived from INT-0002.md. Behaviour and numbers, not implementation. Every limit is a number. -->

## 1. Behaviour

### 1.1 Which responses
"Every response" means every HTTP response the app's code produces, for any method (`GET`, `HEAD`, `OPTIONS`, `POST`, ...) and any path, in both runtimes that serve the app (Lambda function URL and the release container scanned in kind). This includes:

| Kind | Examples (current routes) | Status |
|---|---|---|
| Successful API responses | `GET /api/health`, `GET /api/dogs`, `GET /api/dogs/{breed}` (existing breed) | 200 |
| API caller errors | `GET /api/dogs/{breed}` with an unknown breed (`husky`) or an invalid one (`Bad_Breed`, `..`, 41 characters); unknown path under `/api/` (`/api/nope`); method not allowed (`POST /api/health`, `OPTIONS /api/dogs`); any validation error (422) if one is ever produced | 404, 405, 422 |
| Unknown paths outside `/api/` | `/nope`, `/assets/missing.js`, `/docs`, `/openapi.json` | 404 |
| Unhandled application errors | any exception inside a route that reaches the app's last-resort error handling (for example the S3 listing raising) | 500 |
| The web page | `GET /`, `GET /index.html`, `HEAD /` | 200 |
| Static assets of the web build | `GET /assets/index-<hash>.js`, `GET /assets/index-<hash>.css`, any image or icon in the build | 200 |
| Conditional requests | `GET /` or an asset with a matching `If-None-Match` | 304 |
| Directory redirects | a path to a directory of the web build without the trailing slash, when that directory serves an `index.html` (redirect to the same path with `/`) | 307 |
| Range requests | `GET /` or an asset with `Range: bytes=0-9` (partial content); with `Range: bytes=999999999-` beyond the end (not satisfiable) | 206, 416 |

Out of the guarantee (INT-0002 item 9): responses the Lambda platform generates without running the app's code (function timeout at 10 s, throttling, platform 5xx before the app runs), and the S3 presigned image responses (served by S3).

### 1.2 Common headers (every response in 1.1)
Each response carries each of these headers **exactly once**, with **exactly** this value (byte for byte, case of the value as written).

How they are applied (normative):
- One single app-wide point applies the headers of 1.2–1.4 to the **final** response, after every route, static-file handler and error handler (including the last-resort handler that turns an unhandled exception into the 500) has produced it. No route, static-file path or error path sets them separately, so none can bypass or duplicate them.
- The headers are **set**, not appended: any existing header of the same name (in any letter case) is replaced, so the response ends with exactly one instance carrying the value below.

| Header | Value |
|---|---|
| `X-Content-Type-Options` | `nosniff` |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` |
| `Referrer-Policy` | `no-referrer` |

### 1.3 Content-Type
- Every response with a body (including `HEAD` responses, which carry the `Content-Type` the matching `GET` would carry) has exactly one `Content-Type` that matches the body.
- Text types carry the parameter `charset=utf-8`, written as `<type>; charset=utf-8` (lowercase, one space after the semicolon). Text types are: `text/*` (HTML, CSS, JavaScript as `text/javascript`, plain text), `application/json`, `application/javascript`, `image/svg+xml`.
- Binary types (`image/png`, `image/jpeg`, `image/webp`, `image/x-icon`, `image/gif`) carry no `charset`.
- Exact values (normative). They hold whatever the runtime's file-type detection (operating-system or library MIME tables) would report; the app's own mapping wins for these extensions:

| Response | `Content-Type` |
|---|---|
| All API responses and all JSON errors (200, 404, 405, 422) | `application/json; charset=utf-8` |
| Unhandled error (500) | `text/plain; charset=utf-8` (body unchanged: `Internal Server Error`) |
| `/`, `/index.html`, any `*.html` | `text/html; charset=utf-8` |
| `*.js` asset | `text/javascript; charset=utf-8` |
| `*.css` asset | `text/css; charset=utf-8` |
| `*.png` asset | `image/png` |
| `*.ico` asset | `image/x-icon` |
| `*.svg` asset | `image/svg+xml; charset=utf-8` |
| `206` single range | the `Content-Type` of the full file, as above |
| `206` multiple ranges | `multipart/byteranges; boundary=<boundary>` (no `charset`) |
| `416` with a body | `text/plain; charset=utf-8` |

- A response without a body (`304 Not Modified`, a `307` redirect with an empty body, a `416` with an empty body) carries no `Content-Type`; it still carries the common headers (1.2) and, for HTML paths, the HTML headers (1.4).

### 1.4 HTML responses only
An HTML response is any response whose `Content-Type` is `text/html` (today: `/` and `/index.html`, including a `206` of them), and a `304` for a path that serves HTML. Redirects (`307`) and `416` responses are not HTML responses. Each HTML response additionally carries, exactly once:

| Header | Value |
|---|---|
| `Content-Security-Policy` | `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' https://<image-host>; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; object-src 'none'` |
| `Cross-Origin-Opener-Policy` | `same-origin` |

- The CSP value never contains `unsafe-inline`, `unsafe-eval`, `*`, `data:`, `blob:` or `http:`.
- Non-HTML responses (JSON, plain text, scripts, stylesheets, images, 304s for non-HTML paths) carry **neither** `Content-Security-Policy` nor `Cross-Origin-Opener-Policy`.

### 1.5 The image host (`<image-host>`)
- **Rule:** `<image-host>` = `<bucket>.s3.<region>.amazonaws.com`, where `<bucket>` is the bucket the app lists and presigns images from (deployment setting `DOGS_BUCKET`) and `<region>` is the region the app's S3 client signs for (deployment setting `AWS_REGION`, default `eu-north-1`). This is the virtual-hosted, regional host that the app's presigned image URLs use today (`api/app/main.py`: regional endpoint `https://s3.<region>.amazonaws.com`, virtual addressing; existing test `test_presigned_urls_use_regional_endpoint`).
- **Deployed example** (bucket `sdlc-lab-app-dogs-dev-992382408037`, region `eu-north-1`):
  `<image-host>` = `sdlc-lab-app-dogs-dev-992382408037.s3.eu-north-1.amazonaws.com`, so the header is
  `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' https://sdlc-lab-app-dogs-dev-992382408037.s3.eu-north-1.amazonaws.com; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; object-src 'none'`.
- The host is the same host as in every presigned URL that `GET /api/dogs` returns, and the CSP names no other image host.
- The host comes only from the deployment settings, never from the request (Host header, `X-Forwarded-*`, path, query, any other header). It is fixed for the lifetime of a running app instance and is a single exact hostname, never a wildcard.
- **Validation, fail closed:** `<bucket>` must match `^[a-z0-9][a-z0-9-]{1,61}[a-z0-9]$` (3 to 63 characters, no dots, so the virtual-hosted name stays one TLS-valid label) and `<region>` must equal `eu-north-1`. If `DOGS_BUCKET` is missing or either value fails its check, HTML responses still carry a CSP, with `img-src 'self'` and no S3 host:
  `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; object-src 'none'`. Images then don't display; no other behaviour changes.
- No infrastructure change is needed: both settings already exist in the deployment (`DOGS_BUCKET` set by `infra/main.tf`, `AWS_REGION` set by the Lambda platform; in kind `DOGS_BUCKET=unused-in-kind` and the region defaults to `eu-north-1`). IAM, S3 public-access settings and AWS services are unchanged.

### 1.6 What does not change
- No `Access-Control-*` header on any response, including `OPTIONS` requests carrying `Origin` and `Access-Control-Request-Method`.
- No `Cache-Control` header is added or changed by this change.
- Response bodies, status codes and routes are unchanged (the existing tests `test_health`, `test_lists_only_well_formed_keys`, `test_by_breed`, `test_unknown_or_invalid_breed_is_404`, `test_no_api_docs_exposed` keep passing unchanged).
- Header values never depend on request input; a request cannot add, remove, duplicate or alter any header named in 1.2–1.4 (no CR/LF from input reaches a header).
- The page looks and behaves as today: the gallery loads, the breed filter works, images from S3 display, and the browser reports no CSP violation. The page keeps having no inline scripts, inline styles, `style` attributes, inline event handlers, `eval`/`new Function`, or third-party script, style, font or image origins.

### 1.6a Frontend output handling (SR-003)
- The page renders breed names and image metadata from the API only as text (caption text, `alt` text, `<option>` text and value); a breed or filename containing markup such as `<script>alert(1)</script>` appears literally as text and creates no element and runs no script.
- The page accepts an API `url` as an image `src` only if it parses as an absolute URL with scheme `https:`, no user name or password, no explicit port, and a hostname matching `^[a-z0-9][a-z0-9-]{1,61}[a-z0-9]\.s3\.eu-north-1\.amazonaws\.com$` (the image-host rule of 1.5). The CSP (1.4) narrows this further to the one deployed bucket.
- An entry whose `url` fails the check is not rendered and is not counted in the status text; all other entries render as today. With the API's real data (every URL is a presigned URL on the image host) the page looks exactly as today.
- No new frontend dependency is needed for this or its tests; if one is added it follows SR-027.

### 1.7 Release evidence (deploy)
- The ZAP baseline in the release pipeline scans both `/api/health` and `/` of the release container, and that container serves the same web build that goes into the Lambda zip.
- The deploy does not proceed if the ZAP report contains any alert (risk Low or higher, or reported as WARN or FAIL) from these SR-004 header rules: `10019` Content-Type Header Missing, `10020` Anti-clickjacking Header, `10021` X-Content-Type-Options Header Missing, `10035` Strict-Transport-Security Header, `10038` Content Security Policy Header Not Set, `10055` CSP. ZAP alerts from other rules are kept in the uploaded report and do not stop the deploy (see Decisions, D-4).
- What each check proves: the ZAP gate proves header **presence** (and that the CSP has no flagged weakness) on the release container. That container runs with `DOGS_BUCKET=unused-in-kind`, so its CSP names `https://unused-in-kind.s3.eu-north-1.amazonaws.com`, not the deployed bucket; ZAP therefore never proves the real image host. The post-deploy smoke test is the check of the **real** CSP value, including the S3 host; it fails if the deployed page carries the fallback CSP of 1.5 (no S3 host in `img-src`) or any other host.
- After the deploy, the smoke test fails the workflow unless `GET /` and `GET /api/health` on the deployed function URL carry the exact values of 1.2, `GET /` carries the CSP of 1.4 with `<image-host>` equal to the host of the first presigned URL returned by `GET /api/dogs` and to `<bucket>.s3.eu-north-1.amazonaws.com` for the Terraform output `bucket`, plus `Cross-Origin-Opener-Policy: same-origin`, and neither response carries an `Access-Control-*` header.
- `security/exceptions.yml` EXC-001: its ZAP part ends with this change. Its `reason` is narrowed to the part that remains (no LLM security tester in deploy, because CI calls no AI since change 0001); `sr`, `paths`, `approved_by`, `approved` and `expires` (2026-12-31) are unchanged. `docs/pipeline.md` and `docs/architecture.md` ("Known gaps": SR-004 removed) are updated to match.

## 3. Limits
- Header values are fixed strings: 3 common headers, 2 HTML-only headers, each exactly once per response.
- `<bucket>`: 3–63 characters, pattern in 1.5; `<region>`: exactly `eu-north-1`; `<image-host>`: one hostname, at most 63 + 27 = 90 characters, no wildcard.
- HSTS `max-age` = 31 536 000 s (365 days), with `includeSubDomains`, without `preload`.
- Unchanged: Lambda timeout 10 s, memory 128 MB, presigned URL lifetime 900 s, breed 1–40 characters.
- No new rate limits or quotas (read-only, unauthenticated app; SR-007 concurrency gap is a lab exception).

## 4. Authentication and identities
- None. The app stays public, unauthenticated and read-only; no accounts, sessions, cookies or tokens exist or are added.
- The deploy workflow keeps its existing identity (OIDC role `sdlc-lab-gh-dogs-app-dev`, environment `dev`); no new secret, token or permission.

## 7. Errors and logging
- No new log events and no change to logging (SR-024 log format is a known gap, out of scope per INT-0002). Header values, presigned URLs and request headers are not logged.
- Callers see unchanged error bodies and status codes (1.3, 1.6); error responses carry the same common headers as successes, and HTML-only headers only when the error is HTML (none today).
- A missing or invalid image-host setting is not an error to callers: the fallback CSP (1.5) applies, and the deploy smoke test (1.7) fails the workflow, so the misconfiguration is visible to the owner.
- ZAP gate failure or smoke-test failure: the workflow step fails with the rule IDs or the missing/incorrect header named in the job log; no secret or presigned URL is printed.

## Decisions made by the author

- **D-1 (gap for the final PR, SR-005):** error bodies stay `{"detail": ...}` / `Internal Server Error` instead of `{"error": "<code>", "request_id": "<id>"}`, and unhandled exceptions are not logged as `error.unhandled` with the request ID. Blocked by INT-0002 item 7 (bodies and status codes unchanged) and its out-of-scope list (response bodies; SR-024). Stays an open finding for the owner at the merge to `main`.
- **D-2 (SR-003 frontend check added):** the page now accepts an API image URL only if it is `https:` on the image-host pattern and renders API data only as text (1.6a). With real API data the page looks exactly as today; INT-0002 forbids changes to the page's look, not this check.
- **D-3 (gap for the final PR, SR-022):** the bucket policy has no deny for `s3:TlsVersion` below `1.2`, and there is no TLS 1.1 handshake test. Blocked by INT-0002 item 8 (infrastructure only as needed for the image host). Stays an open finding for the owner at the merge to `main`.
- **D-9 (gap for the final PR, SR-006):** the S3 client has no connect ≤ 3 s / read ≤ 5 s timeouts and no bounded retries (at most 2, with backoff, idempotent only); an S3 failure gives `500`, not `503` with the SR-005 body; there is no failing-S3-stub test asserting `503`. Blocked by INT-0002's out-of-scope list ("Other known gaps: … SR-006 timeouts") and item 7 (status codes unchanged). Stays an open finding for the owner at the merge to `main`.
- **D-4 (ZAP gate scope):** the deploy stops only on the SR-004 header rules (1.7). Other ZAP alerts that need headers SR-004 does not require (for example `10063` Permissions-Policy, `90004` site isolation, `10049`/`10015` caching, the last excluded by the owner) don't stop the deploy, because adding headers beyond SR-004 would go past INT-0002.
- **D-5 (image host fail-closed):** a missing or invalid `DOGS_BUCKET`, or a region other than `eu-north-1`, gives a CSP without any S3 host (images blocked) rather than a CSP built from an unvalidated value. Dotted bucket names are rejected because virtual-hosted TLS does not cover them.
- **D-6 (304, HEAD, OPTIONS, 405, 307, 206, 416 included):** "every response" is read literally, so these carry the headers too; a 304 or 206 for an HTML path keeps CSP and COOP.
- **D-7 (EXC-001 narrowed, not removed):** its ZAP part ends here; the LLM-security-tester part cannot end in this change because CI calls no AI (change 0001), so the entry stays with a narrowed reason and its original expiry 2026-12-31.
- **D-8 (HSTS without `preload`):** SR-004's exact value has no `preload`; it is not added.
